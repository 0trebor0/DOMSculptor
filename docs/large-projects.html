Large-project architecture

Organise by feature, own every lifetime.

DOMSculptor remains a DOM toolkit. Application boundaries stay explicit and browser APIs remain available.

Recommended structure

app/
  bootstrap.js
  routes.js
  services/
    session.js
    users.js
  features/
    account/
      component.js
      state.js
      test.js
  shared/
    components/
    accessibility/

Each feature exports a component factory. Route scopes own feature components, effects, listeners, and pending async work. Services expose browser-oriented functions or signals without importing view code.

Routing with browser APIs

let active = null;

function navigate(url) {
  history.pushState(null, "", url);
  active?.dispose();
  active = routes.get(location.pathname)();
  sculptor.mount(active, "#app");
}

addEventListener("popstate", () => navigate(location.href));

Dispose the previous route before mounting the next. Keep route matching, guards, and URL parsing outside the runtime.

Lazy feature loading

import { createLazyComponent } from "domsculptor/lazy";

const Reports = createLazyComponent(
  sculptor,
  () => import("./features/reports/component.js"),
  { loading: "Loading reports…" }
);

The optional entry uses native dynamic imports, aborts its loader signal on disposal, exposes loading/success/error status, and disposes the loaded child component.

Error boundaries

const SafeAccount = sculptor.errorBoundary(
  Account,
  (error) => ({
    root: sculptor.tree({ tag: "p", text: "Account could not be opened." }),
    api: { error }
  })
);

Boundaries clean failed component-construction scopes before creating fallback UI. Report the original error from the fallback API or application telemetry.

Testing

import { createTestHarness } from "domsculptor/testing";

const test = createTestHarness();
const view = Account({ service: fakeService });
test.mount(view);
test.flush();
test.assertClean();
test.dispose();

The harness provides an isolated development runtime, fixture root, deterministic flushing, captured warnings, and component-leak assertions.

Accessibility patterns

  • Dialogs: move focus inside on mount, restore it on dispose, and handle Escape.
  • Forms: associate labels and errors, focus the validation summary, and bind aria-invalid.
  • Async regions: announce completion through a polite native live region.
  • Menus and tabs: use roving tabindex and native keyboard events.

Service boundaries

Pass services through component props or minimal context keys. Fetch, WebSocket, authentication, validation, and caching policies remain application code. Accept an AbortSignal for every cancellable operation.
