Guide

Routing, and why each view owns its lifetime.

router() maps path patterns to views, keeps one mounted, and disposes the previous view and its scope on every change. That last part is the reason it exists: without it, every route change leaks whatever the view created.

Two runnable examples accompany this guide: example/router/index.html for the basics, and example/router/advanced.html for ten routes with guards, redirects, and nested parameters. Each has a verifier that drives it in a real browser.

Step one

The smallest router

A route is a pattern and a function returning an element. Nothing else is required.

const router = sculptor.router({
  "/": () => sculptor.tree({ tag: "h1", text: "Home" }),
  "/about": () => sculptor.tree({ tag: "h1", text: "About" })
}, { parent: "#app" });

The matching route mounts immediately. router.navigate("/about") changes route programmatically, and ordinary links work too once you choose a mode.

Matching

Patterns and matching

Patterns are split on /. A segment beginning : captures that segment; * matches anything; every other segment is matched literally, with regular-expression characters escaped. 

"/docs"                  // exactly /docs
"/docs/:section"         // /docs/state
"/docs/:section/:page"   // /docs/state/effects
"/a.b"                   // exactly /a.b — never /axb

That last line matters more than it looks. A dot in a literal segment is a dot, not "any character", so a route containing a version number or a filename matches only itself.

Routes are tried in the order they are declared, and the first match wins. Put * last.

Data from the URL

Parameters

Every view receives a snapshot: { path, route, params, scope }. params holds the captured segments, already URL-decoded. 

"/people/:id": ({ params }) => Person({ id: params.id })

// #/people/ada%20lovelace  →  params.id === "ada lovelace"

route is the pattern that matched, which is useful for analytics and for deciding what a breadcrumb should say. path is the actual path.

The part that surprises people

Catch-alls: * and /* are different

* is a whole-path wildcard. It captures everything, including the leading slash. /* anchors that slash as a literal, so the capture is the remainder. 

"*"          // /deep/path  →  params.rest === "/deep/path"
"/*"         // /deep/path  →  params.rest === "deep/path"
"/search/*"  // /search/keyed lists  →  params.rest === "keyed lists"

Use a bare * for a not-found route, and a prefixed form such as /search/* or /files/* when you want everything below a path as one value.

Choosing a mode

Hash or history

By default the router reads location.pathname and navigates with pushState, which needs a server that returns your application for every URL. Pass { hash: true } to route on the fragment instead. 

sculptor.router(routes, { parent: "#app" });                // /posts/hello
sculptor.router(routes, { parent: "#app", hash: true });    // #/posts/hello

Hash mode works from the file system, from static hosting with no rewrite rules, and inside browser extensions. Back and forward work in both modes, through popstate and hashchange respectively.

The reason the router exists

Each view runs in its own scope

A view function runs inside a disposal scope the router creates. Signals, computed values, effects, subscriptions, and elements made there belong to the route, and are released when you leave it. 

"/dashboard": () => {
  const tick = sculptor.signal(0);
  const timer = setInterval(() => tick.update(n => n + 1), 1000);
  const root = sculptor.tree({ tag: "p", text: sculptor.computed(() => String(tick.get())) });

  root.onDispose(() => clearInterval(timer));   // your own resources still need this
  return root;                                  // the signal and computed do not
}

The scope is disposed before the view's elements, and a scope releases in reverse order of creation, so a subscription made after the element it writes into is released first. Create the element, then subscribe, and a callback cannot outlive what it renders into.

Slow work

Asynchronous views

A request can outlive its route. The snapshot's scope answers whether the route is still on screen, which is the guard that keeps a late response from writing into a disposed view. 

"/posts/:slug": ({ params, scope }) => {
  const post = sculptor.signal(null);

  loadPost(params.slug).then(value => {
    if (scope.disposed) return;   // the reader navigated away; drop it
    post.set(value);
  });

  return sculptor.tree({
    tag: "article",
    text: sculptor.computed(() => post.get()?.title ?? "Loading…")
  });
}

Without the guard, post.set(value) throws, because writing to a disposed signal is an error rather than a silent no-op. That is deliberate: it turns a whole class of leak into a visible failure.

Access and redirects

Guards and redirects

A guard is an early return in the view. Redirecting from inside a view is safe: the router schedules the next render rather than reentering, so this view still returns an element and is disposed a moment later. 

let intended = null;

const Settings = ({ params }) => {
  if (!session.user.get()) {
    intended = `/people/${params.id}/settings`;
    router.replace("/login");
    return sculptor.tree({ tag: "p", text: "Redirecting…" });
  }
  return SettingsView({ id: params.id });
};

const Login = () => {
  // …on success:
  const target = intended || "/";
  intended = null;
  router.replace(target);
};

Use replace rather than navigate for a redirect, so the intermediate URL does not become a history entry the back button returns to. The same pattern keeps an old URL shape working: 

"/legacy/:id": ({ params }) => {
  router.replace(`/people/${params.id}`);
  return sculptor.tree({ tag: "p", text: "Redirecting…" });
}

Navigation state

Active links

router.current is a readable snapshot, so a link's active state is a binding rather than something you track alongside the router. 

sculptor.tree({
  tag: "a",
  attributes: { href: "#/docs" },
  text: "Docs",
  class: {
    active: sculptor.computed(() => router.current.get().path.startsWith("/docs"))
  }
});

Matching on a prefix keeps a section highlighted while a nested page is open. Compare exactly (=== "/") for a home link, or every route would light it up.

The same snapshot drives titles and breadcrumbs:

router.current.subscribe(snapshot => {
  document.title = snapshot.route === "/" ? "Home" : `${snapshot.path} · Docs`;
}, { immediate: true });

Composition

Components as views

A view may return a DomElement or a component instance, so sculptor.component() factories work directly and receive the snapshot as props. 

const Post = sculptor.component(({ slug }) => {
  const root = sculptor.tree({ tag: "article", text: slug });
  return { root, api: { refresh: () => {} } };
});

sculptor.router({ "/posts/:slug": ({ params }) => Post({ slug: params.slug }) }, { parent: "#app" });

A component brings its own scope, which the router disposes along with the one it created for the view.

Teardown

Stopping

stop() removes the listener, disposes the mounted view and its scope, and is idempotent. The runtime owns the router, so disposing the runtime stops it too — you rarely need to call stop() yourself. 

router.stop();
router.stopped;      // true

sculptor.dispose();  // also stops every router the runtime owns

Worth knowing

Common mistakes

Expecting * to drop the leading slash

It does not. Use /* when you want the remainder without it.

Writing to a signal after leaving the route

Guard asynchronous continuations with scope.disposed. The write throws otherwise.

Using navigate for a redirect

It leaves the intermediate URL in history, so the back button lands on the route that redirected. Use replace.

Highlighting a home link with a prefix match

"/".startsWith("/") is true for every path. Compare exactly for the root.

Unwinding a route by hand

Disposing the previous view yourself is what the router already does. If you find yourself keeping an activeRoute variable, you are re-implementing it.

Putting * first

The first matching pattern wins, and * matches everything. Declare it last.
