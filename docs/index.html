Direct DOM · useful reactivity · predictable cleanup

Small interfaces deserve a small mental model.

DOMSculptor is a tiny, dependency-free, client-side reactive DOM toolkit for widgets, browser extensions, embedded interfaces, progressive enhancement, and small applications.

import DomSculptor from "domsculptor";

const sculptor = new DomSculptor();
const count = sculptor.signal(0);
const button = sculptor.create("button");

count.bindText(button, value => `Count: ${value}`);
button.on("click", () => count.update(value => value + 1));

Five-minute start

From an empty page to reactive UI.

  1. Install: run npm install domsculptor.
  2. Add a mount point: put <div id="app"></div> in the page.
  3. Create: elements are detached until you mount them.
  4. Connect: bind a signal and add browser events.
  5. Clean up: call dispose() at route, page, or widget teardown.
import DomSculptor from "domsculptor";

const sculptor = new DomSculptor();
const message = sculptor.signal("Ready");
const status = sculptor.create("p");
const button = sculptor.create("button").setText("Update");

message.bindText(status);
button.on("click", () => message.set("Updated"));

const view = sculptor.tree({
  tag: "section",
  children: [status, button]
});

sculptor.mount(view, "#app");

// Teardown:
view.dispose();
message.dispose();

Mental model: create detached DOM, connect behavior, mount deliberately, then dispose ownership. Start with these four operations before learning the rest of the API.

DOM creation and wrapping

Create detached. Mount deliberately.

Compose

create() and tree() create detached, safe, text-first DOM.

Connect

mount(), unmount(), and adopt() make ownership explicit.

Clean up

dispose() permanently removes listeners, bindings, descendants, and references.

Ordinary text and tree APIs never accept raw HTML. If native HTML APIs are used, sanitisation remains the caller's responsibility.

Signals, computed values, effects, and batching

Immediate values. One queued DOM pass.

const first = sculptor.signal("Ada");
const last = sculptor.signal("Lovelace");
const full = sculptor.computed(
  () => `${first.get()} ${last.get()}`,
  [first, last]
);

const stop = sculptor.effect(() => {
  document.title = full.get();
}, [full]);

sculptor.batch(() => {
  first.set("Grace");
  last.set("Hopper");
});

stop();
full.dispose();

Keyed lists

Move nodes; do not rebuild identity.

Stable keys preserve nodes, focus, selection, and row-local state. Duplicate keys throw before the DOM changes.

todos.list(list, {
  key: todo => todo.id,
  render: todo => sculptor.tree({
    tag: "li",
    children: [
      { tag: "span", text: todo.text },
      { tag: "button", text: "Delete" }
    ]
  }),
  update: (row, todo) => {
    row.child.find("span").setText(todo.text);
  }
});

list.dispose();
todos.dispose();

Components and disposal scopes

A factory and a scope—not a hidden renderer.

const Counter = sculptor.component(props => {
  const count = sculptor.signal(props.initial ?? 0);
  const root = sculptor.tree({
    tag: "button",
    text: count,
    on: { click: () => count.update(value => value + 1) }
  });
  return { root, api: { count } };
});

const counter = Counter({ initial: 2 });
sculptor.mount(counter, "#app");
counter.dispose();

onMount runs once per element lifetime, parent before children. onUnmount runs child-first on temporary detachment. onDispose runs once, child-first, before permanent cleanup. Moving a node never disposes it, and cleanup continues after hook errors with AggregateError for multiple failures.

Forms

Native controls keep native semantics.

Bind text inputs, textareas, selects, multiple selects, checkboxes, radio groups, numbers, and custom controls. Equal writes are skipped to preserve the caret, and composition events protect IME input.

accepted.bind(checkbox);
quantity.bind(numberInput);
tags.bind(multipleSelect, { multiple: true });

formScope.dispose();

Async state

Cancellation is part of correctness.

const users = sculptor.asyncState([]);

const { status, error } = await users.run(({ signal }) =>
  fetch("/users?q=ada", { signal }).then(response => response.json())
);
// run() resolves with the snapshot and never rejects.

users.cancel();
users.reset();

Accessibility and security

Browser behavior remains visible.

  • Bind boolean ARIA attributes and native properties directly.
  • Preserve focus and selection during keyed moves.
  • Use labels, live regions, keyboard events, and native focus APIs.
  • Run under strict CSP without eval, generated functions, or inline runtime styles.

TypeScript

Strong contracts without changing the JavaScript source layout.

Declarations ship from types/index.d.ts; the runtime remains entirely in src/index.js.

const input = sculptor.create("input");
input.html?.select(); // HTMLInputElement

const form = sculptor.store({ name: "Ada", age: 36 });
form.set("age", 37);       // number required

const Account = sculptor.component(
  (props: { userId: string }) => ({
    root: sculptor.create("section"),
    api: { userId: props.userId }
  })
);

Native tags, events, component props and APIs, context keys, stores, async state, keyed lists, tree configuration, testing utilities, and lazy components are compile-checked in CI.

API reference

One direct-DOM vocabulary.

Core

create · createProgressively · rendering · createIn · mount · unmount · adopt · tree · when

Reactive

signal · store · computed · effect · batch · flush · asyncState

Element

child · attribute · class · text · attr · focus · events · lifecycle · dispose

Composition

createScope · component · createContext · createContextKey

Core public APIs are exported from domsculptor. Optional testing and lazy-loading helpers use domsculptor/testing and domsculptor/lazy.

Creation and ownership

create(tag, parent?, callback?) returns a detached typed wrapper unless a parent is supplied. createIn(parent, tag) inserts immediately. mount, unmount, adopt, wrap, tryWrap, and tryMount make failure and lifetime explicit.

Elements

setText, text, attr, classToggle, styleValue, bindProperty, child operations, traversal, focus helpers, lifecycle hooks, native events, delegation, and dispose.

Reactivity

signal/state, typed store/data, lazy computed, cleanup-aware effect, batch, and test-oriented flush. Values update immediately; DOM work is microtask queued and deduplicated.

Rendering and composition

create, createProgressively, rendering, tree, when, keyed list, component, createScope, and hierarchical context. Progressive creation mounts one element per animation frame; regular parented creation is synchronous. Component roots may be a node, wrapper, or DocumentFragment.

Forms and async

bind/sync handles native controls, IME, custom accessors, properties, caret-safe equal writes, and event selection. asyncState exposes idle, loading, refreshing, success, and error snapshots plus run, retry, cancel, and reset.

Error policy

Programmer errors throw TypeError; creation and mounting failures throw; explicitly searching methods may return null; tryWrap and tryMount are non-throwing. Subscriber and cleanup failures are aggregated.

Performance guidance

Measure identity and cleanup before speed.

Prefer keyed rows, use createProgressively for large initial collections, batch related writes, delegate repeated events, dispose scopes, and benchmark production builds. Report the browser, device, raw code, median, variance, and compressed bundle size.

Migration guide

Move from implicit creation to explicit lifetime.

  1. Keep create(tag); it is detached in 2.0.
  2. Replace code that relied on implicit body insertion with mount() or createIn().
  3. Use unmount() temporarily and dispose() permanently.
  4. Replace full list renderers with stable keyed configuration.
  5. Replace the removed jsontohtml() API with detached tree() configurations.

Coming from 2.0

  1. child.append() and prepend() now return the element that was added rather than the container. Code that chained a second append onto the first was adding a sibling and now adds a descendant; split it into two statements on the container, or use tree().
  2. asyncState.run() and retry() resolve with the resulting snapshot and no longer reject or resolve with the data. Replace try/catch and .catch(() => {}) around them with a check of the returned snapshot's status and error.
  3. bindHidden() is now the exact mirror of bindVisible() and toggles inline display; it previously set the native hidden property. Use bindProperty(element, "hidden") if you need the old mechanism.
  4. computed(fn) and effect(fn) without a dependency list now track the signals they read instead of never re-running. Pass [] to keep the old evaluate-once behaviour.
  5. Dispose hooks now run with the subtree already out of the document. The element disposal started at has a null parentNode; its descendants keep theirs, because they are discarded with it rather than each removing itself. Read an element's position before disposing it, not from the hook.

Compatibility policy

Stable majors, explicit migrations.

DOMSculptor follows semantic versioning. Patch releases fix compatible defects, minor releases add compatible APIs, and breaking behavior is reserved for major releases with changelog and migration entries. Deprecated APIs remain for at least one minor line before removal unless they create a security or correctness hazard.

Comparison and non-goals

Deliberately not a universal framework.

DOMSculptor favors direct browser APIs over virtual DOM, JSX transforms, compilers, SSR, hydration, CSS-in-JS, animation engines, HTTP clients, and global state ecosystems. Client-side routing is no longer on that list: router() ships with the library.
